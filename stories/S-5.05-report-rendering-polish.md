# S-5.05: Report HTML visual polish — hero band, severity-tinted finding cards, dark-mode awareness

## Narrative

- **As an** OT defender handing the report to a plant manager / IT director / on-site engineer
- **I want** the HTML report to look like a finished, branded artifact
  instead of a generic plain-CSS template
- **So that** the report reads like something a professional tool produced —
  severity is instantly scannable, the brand mark is present, and the
  document is print-friendly + dark-mode aware

## Acceptance Criteria

### AC-001 (BC-8.01.003 — hero band with inline brand mark)

- `templates/report.html` includes a `<header class="hero">` element at the
  top of the body, containing:
  - An inline `<svg>` brand mark (no external `<img>` or font file) — a
    hexagonal outline with three connected circuit-trace dots, matching
    the wordmark established in `media/otsniff-logo.png`. Monochrome,
    `currentColor`-driven so it adapts to theme.
  - The report title `otsniff report`.
  - A sub-line citing the input file, generated timestamp, and `otsniff` version.
  - The four headline stat tiles (packets / bytes / hosts / findings)
    inside the hero, NOT below it.
- **Test:** Existing `tests/snapshot.rs` snapshot regenerates. The new
  snapshot must contain literal substring `<svg` AND `class="hero"` AND
  `class="stats"` inside the `<header>` element. Verified by an additional
  unit test in `src/report.rs::tests` that asserts these substrings appear
  in the rendered output for any non-trivial fixture.

### AC-002 (BC-8.01.003 — severity-tinted finding cards)

- Each `.finding` card has a soft-tinted background colored by its
  severity class:
  - `.sev-critical` → soft red tint
  - `.sev-high` → soft orange tint
  - `.sev-medium` → soft amber tint
  - `.sev-info` → soft blue tint
- The 4px left border that already exists is preserved. The tint
  REPLACES the previous uniform `var(--card)` grey.
- **Test:** Unit test in `src/report.rs::tests` asserts that for a
  fixture with at least one critical finding, the rendered HTML
  contains the class chain `.finding.sev-critical` (already the case)
  AND a CSS rule `.finding.sev-critical { ... background: var(--crit-soft) ... }`
  is present in the embedded `<style>`. (Substring grep is sufficient
  — the test is structural, not visual.)

### AC-003 (BC-8.01.003 — dark mode via prefers-color-scheme)

- The embedded `<style>` block includes a `@media (prefers-color-scheme: dark)`
  section that overrides the CSS custom properties `--bg`, `--bg-soft`,
  `--fg`, `--muted`, `--line` to dark-mode equivalents.
- **Test:** Unit test asserts the `@media (prefers-color-scheme: dark)`
  substring appears in the rendered HTML.

### AC-004 (BC-8.01.003 — print-friendly stylesheet)

- The existing `@media print` block is preserved and extended to
  force-preserve color on the hero band and badges via
  `-webkit-print-color-adjust: exact; print-color-adjust: exact;` so
  severity remains scannable on printed pages.
- **Test:** Unit test asserts the `print-color-adjust: exact`
  substring appears in the rendered HTML.

### AC-006 (BC-8.01.003 — logo fidelity to media/otsniff-logo.png) — amended 2026-05-12

The inline SVG in `<header class="hero">` must visually approximate
the brand mark shipped at `media/otsniff-logo.png` (committed via
PR #49). Specifically:

- Pointy-top hexagonal outline (vertices at top center and bottom
  center; flat sides on left and right).
- Three connected nodes (filled circles) inside the hexagon.
- The traces connecting the nodes use **90° corners only** (PCB-style
  step pattern). No diagonal lines.
- The trace path enters from the lower-left of the hexagon, steps up
  via right-angle turns, and exits / terminates at a node in the
  upper-right.
- The whole SVG remains monochrome `currentColor` so it adapts to
  light + dark theme.

**Test:** A unit test asserts the rendered HTML contains:
- `<polyline` (the trace path; not `<line>` segments)
- At least 3 `<circle` elements with `fill="currentColor"` (the nodes)
- `stroke-linejoin="round"` (the 90° corners are softened)

### AC-007 (BC-8.01.003 — collapsible table sections) — amended 2026-05-12

The Asset inventory and Top flows tables are each wrapped in a
`<details open>` element. The `<summary>` contains the section title
("Asset inventory" / "Top flows") plus optionally a row count.
Default state is `open` so the report prints fully expanded.

- The two existing `<h2>` headings for those sections are REPLACED by
  the `<summary>` element (or kept inside the summary — implementer's
  choice, but the visual hierarchy must remain).
- `<details>` elements are not nested inside other `<details>`.
- The hero band, findings list, and AI section remain non-collapsible.

**Test:** A unit test asserts the rendered HTML contains TWO
`<details open>` elements (one for assets, one for flows), each
followed by a `<table>`. Search is NOT in scope (would require JS;
user opted for collapse-only).

### AC-005 (snapshot-test regen reviewed, not blanket-accepted)

- The existing `tests/snapshot.rs` HTML snapshots will regenerate.
  Implementer MUST review the snapshot diff with `cargo insta review`
  (NOT `INSTA_UPDATE=always`) and accept only intentional changes
  matching ACs 1–4.
- Data-shape changes (any difference in count, ordering, or content of
  findings / assets / flows / numbers / timestamps) are forbidden —
  those would indicate a bug elsewhere. Only structural / styling /
  layout differences are acceptable.
- **Test:** After implementation, `git diff develop..HEAD -- tests/snapshots/`
  must show diffs only in the `<head><style>...</style></head>` region,
  the `<header class="hero">` insertion, and class-name attributes — not
  in any per-row data field.

  --fg:        #0f1115;
  --fg-on-dark:#e6e9ee;
  --muted:     #6b7280;

  --info:      #2563eb;   --info-soft: #eff6ff;

Severity-card tint maps: `.sev-critical{background:var(--crit-soft)}` etc.

Hero band: `background: var(--bg-strong); color: var(--fg-on-dark)`; SVG mark uses `currentColor` so it inverts cleanly with the theme.

## Inline-SVG mark (drop-in) — amended 2026-05-12 per AC-006

The original sketch used diagonal lines; the brand mark uses
PCB-style right-angle steps. Replacement:

```html
<svg class="logo" viewBox="0 0 64 64" xmlns="http://www.w3.org/2000/svg" aria-label="otsniff" role="img">
  <!-- Pointy-top hexagon outline -->
  <path d="M32 4 L56 18 L56 46 L32 60 L8 46 L8 18 Z"
        fill="none" stroke="currentColor" stroke-width="2.5" stroke-linejoin="round"/>
  <!-- Circuit trace: bottom-left to top-right, 90° steps only -->
  <polyline points="18,46 26,46 26,38 40,38 40,26 50,26"
            fill="none" stroke="currentColor" stroke-width="2"
            stroke-linecap="round" stroke-linejoin="round"/>
  <!-- Nodes -->
  <circle cx="18" cy="46" r="3" fill="currentColor"/>
  <circle cx="26" cy="38" r="2.6" fill="currentColor"/>
  <circle cx="40" cy="26" r="2.6" fill="currentColor"/>
  <circle cx="50" cy="26" r="3" fill="currentColor"/>
</svg>
```
