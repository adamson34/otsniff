# S-8.01: mDNS / NetBIOS-NS / LLMNR hostname extraction

## Narrative

- **As an** OT defender at a site with no DHCP coverage (air-gapped OT VLAN,
  static-IP PLCs, or a capture window that missed DHCP exchanges)
- **I want** otsniff to extract device hostnames from mDNS, NetBIOS Name
  Service, and LLMNR traffic
- **So that** assets appear with human-readable labels (`HMI-LINE-3`,
  `ENG-WS-01`) in the inventory and finding evidence even when DHCP
  option-12 packets are absent from the capture

## Acceptance Criteria

### AC-001 — mDNS A-record hostname extraction (traces to BC-1.02.010 postcondition)

New module `src/parse/mdns.rs` exposes:

```rust
pub struct MdnsHostname { pub name: String, pub ip: Ipv4Addr }
pub fn parse(payload: &[u8]) -> Vec<MdnsHostname>
```

- Parses the DNS message format; iterates the Answer section (`ANCOUNT` records
  starting after the question section).
- For each Answer record with RRTYPE 0x0001 (A) and RRCLASS 0x0001 (IN):
  extracts the owner name and RDATA IPv4 address.
- **Normalization (traces to BC-1.02.013 precondition):** strips trailing
  `.local.` (with dot) or `.local` (without trailing dot) from the owner
  name; discards the record if the resulting name is empty.
- **Compression pointers (traces to BC-1.02.010 precondition):** if any
  label in the owner name starts with byte 0xC0 (DNS compression pointer
  indicator), the parser returns an empty `Vec` for the entire message — no
  partial insertion.
- Returns empty `Vec` for any truncation, malformed length, bad question
  count parsing, or non-DNS payload; never panics.
- **Tests:** inline `#[cfg(test)]` fixtures including:
  - A record for `HMI-LINE-3.local.` resolving to `10.0.0.5` → name `HMI-LINE-3`
  - A record without `.local` suffix (name preserved as-is, trailing dot stripped)
  - A record whose owner name contains a compression pointer (0xC0) → empty Vec
  - Payload shorter than DNS header (12 bytes) → empty Vec
  - ANCOUNT=0 → empty Vec

### AC-002 — NetBIOS-NS workstation-name extraction (traces to BC-1.02.011 postcondition)

New module `src/parse/netbios.rs` exposes:

```rust
pub struct NetBiosHostname { pub name: String }
pub fn parse_registration(payload: &[u8]) -> Option<NetBiosHostname>
```

- Minimum payload length check: 13 bytes (12-byte NBNS header + 1-byte label
  length).
- Reads the 16-bit flags field at bytes 2–3 (big-endian); checks:
  - QR bit (bit 15) == 0 (query direction)
  - OPCODE bits (bits 11–14) == 5 (Name Registration)
  - Returns `None` if either check fails.
- Reads QNAME starting at byte 12: first byte must be 32 (the first-level
  encoded label length); reads the next 32 bytes.
- **First-level decode (traces to BC-1.02.011 postcondition):** for each
  consecutive pair (H, L) of the 32 bytes: `decoded[i] = ((H - b'A') << 4) | (L - b'A')`.
  Result is a 16-byte array. Returns `None` if any byte in the 32-byte
  block is < b'A' or > b'P' (outside the valid encoding alphabet).
- **Normalization (traces to BC-1.02.013 precondition):** trims trailing
  0x20 (space) bytes from decoded bytes 0..15; drops the 16th byte (suffix).
  Returns `None` if the resulting name is empty (all spaces).
- Discards the `name` if it contains only null bytes (0x00).
- **Tests:** inline fixtures including:
  - Valid NBNS registration for `PLC-LINE3\x20\x20\x20\x20\x20\x20\x20\x20\x00` →
    name `PLC-LINE3`
  - All-spaces name (after decode) → `None`
  - Wrong OPCODE (e.g., Name Query = 0) → `None`
  - Truncated payload (< 13 bytes) → `None`
  - Encoding byte outside A–P alphabet → `None`

### AC-003 — LLMNR A-record hostname extraction (traces to BC-1.02.012 postcondition)

New module `src/parse/llmnr.rs` exposes:

```rust
pub struct LlmnrHostname { pub name: String, pub ip: Ipv4Addr }
pub fn parse(payload: &[u8]) -> Vec<LlmnrHostname>
```

- Parses DNS message format (LLMNR shares the RFC 1035 wire format).
- Checks the QR bit (bit 15 of the 16-bit flags at bytes 2–3, big-endian):
  returns empty `Vec` if QR == 0 (query — only responses carry A answers).
- Iterates the Answer section for A records (RRTYPE 0x0001, RRCLASS 0x0001).
- **Normalization (traces to BC-1.02.013 precondition):** strips trailing
  dot from the owner name; discards the record if the resulting name is empty.
- **Compression pointers:** same rejection rule as mDNS parser (BC-1.02.012
  precondition): 0xC0 byte in any name label → return empty `Vec`.
- Returns empty `Vec` for truncation, malformed payloads, or ANCOUNT=0;
  never panics.
- **Tests:** inline fixtures including:
  - Valid LLMNR response with A record for `ENG-WS-01` → `10.0.1.20`
  - LLMNR query (QR=0) → empty Vec
  - Response with compression pointer in name → empty Vec
  - Payload < 12 bytes → empty Vec

### AC-004 — Observer wiring (traces to BC-1.02.013 postcondition + BC-1.02.010/011/012 integration)

In `src/observe.rs`, `observe_udp` extended with three new UDP-port branches:

```rust
// UDP/5353 mDNS
if pkt.src_port == 5353 || pkt.dst_port == 5353 {
    for h in mdns::parse(&pkt.payload) {
        self.obs.hostnames.insert(IpAddr::V4(h.ip), h.name);
    }
}

// UDP/137 NetBIOS-NS
if pkt.src_port == 137 || pkt.dst_port == 137 {
    if let Some(h) = netbios::parse_registration(&pkt.payload) {
        self.obs.hostnames.insert(pkt.src_ip, h.name);
    }
}

// UDP/5355 LLMNR
if pkt.src_port == 5355 || pkt.dst_port == 5355 {
    for h in llmnr::parse(&pkt.payload) {
        self.obs.hostnames.insert(IpAddr::V4(h.ip), h.name);
    }
}
```

- All three branches use `BTreeMap::insert` (last-write-wins, temporal
  precedence per BC-1.02.013). No priority ordering between sources.
- `classify_flow` gains UDP/5355 → `"llmnr"` label.
- **Tests:** observer integration test with synthetic multi-protocol sequence:
  1. mDNS packet naming `10.0.0.1` as `PLC-A` → obs.hostnames[10.0.0.1] == "PLC-A"
  2. DHCP packet naming `10.0.0.2` as `HMI-B` → obs.hostnames[10.0.0.2] == "HMI-B"
  3. NetBIOS-NS packet from `10.0.0.3` naming itself `ENG-WS` → obs.hostnames[10.0.0.3] == "ENG-WS"
  4. LLMNR response naming `10.0.0.4` as `SCADA-SRV` → obs.hostnames[10.0.0.4] == "SCADA-SRV"
  5. Second mDNS packet naming `10.0.0.1` as `PLC-A-NEW` (later timestamp) →
     obs.hostnames[10.0.0.1] == "PLC-A-NEW" (last-write-wins confirmed)

## Scrub Stance

### 1. What does this feature extract?

- **mDNS:** owner name of DNS A record answers on UDP/5353, after stripping
  `.local` suffix (e.g., `HMI-LINE-3.local.` → `HMI-LINE-3`), associated
  with the RDATA IPv4 address.
- **NetBIOS-NS:** first-level-decoded workstation name from NBNS Registration
  Requests on UDP/137, trailing spaces and suffix byte removed, associated
  with the packet source IP.
- **LLMNR:** owner name of DNS A record answers on UDP/5355 responses, trailing
  dot stripped, associated with the RDATA IPv4 address.

### 2. What does this feature render?

Same surfaces as DHCP hostname extraction (P0-3):
- Hostname column in the asset inventory (HTML and markdown).
- `Asset.hostname: Option<String>` field.
- JSON output via `--json` (the inventory struct).
- AI prompt (via the scrub layer — as `name_NNN` pseudonym, never as raw text).

No new render surfaces introduced.

### 3. What's the BCSI classification?

**High** for all three sources. OT device names (e.g., `LINE-3-PLC`,
`ACME-SUB-EAST`, `ENG-WS-01`) are NERC CIP-011 BCSI: they identify the asset's
function and location even when the IP is not meaningful. Same classification as
DHCP hostnames (P0-3). NetBIOS workgroup names (if ever extracted as a separate
field) would be Medium; they are not extracted by this story.

### 4. What's the scrub stance?

- **Pseudonym class:** existing `name_NNN` (ADR-0006; no amendment needed).
  All new hostnames flow through the same `scrub_map.mint_name(hostname)` path
  as DHCP hostnames.
- **Leak detector coverage:** map-value check (`ensure_no_map_values`,
  BC-5.02.002). Hostnames have no clean regex shape; they are protected by the
  full-value scan of the scrub map. The regex check (BC-5.02.001) does not
  apply to hostnames but is not needed here.
- **New BCSI surface:** zero. The three new extractors write into `obs.hostnames`
  which is already within the scrub boundary. No new field, no new render path.
- **Test that enforces it:** the existing
  `invariant_no_real_values_reach_ai_provider` snapshot test exercises the
  map-value check against the full obs.hostnames content. As long as new
  hostnames enter via `obs.hostnames`, they are automatically covered.

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | mDNS/LLMNR name contains DNS compression pointer (0xC0 byte) | Parser returns empty Vec; no panic; no insertion |
| EC-002 | NetBIOS QNAME label length ≠ 32 (not first-level encoded) | `parse_registration` returns None; no panic |
| EC-003 | NetBIOS name decodes to all 0x20 (space) bytes | `parse_registration` returns None; no insertion |
| EC-004 | NetBIOS encoding byte outside A–P (0x41–0x50) alphabet | `parse_registration` returns None; no panic |
| EC-005 | mDNS A record with no `.local` suffix (some implementations omit it) | Strip trailing dot only; insert name as-is if non-empty |
| EC-006 | LLMNR query (QR=0) on UDP/5355 | Parser returns empty Vec; no insertion |
| EC-007 | Zero-length name after normalization | Record discarded; no insertion |
| EC-008 | Name > 253 characters (exceeds DNS limit) | Parser rejects (label walk overruns or exceeds DNS name bound); returns empty Vec/None |
| EC-009 | Multiple A records in a single mDNS or LLMNR response | Each valid A record yields a separate (name, ip) pair; all inserted |
| EC-010 | Same IP named by two successive mDNS packets (different names) | Last packet wins; obs.hostnames[ip] holds the later name |
| EC-011 | mDNS multicast src_ip (224.0.0.251): src_ip is NOT the asset's IP | mDNS A record RDATA IP is used, not src_ip — this is correct behavior |

## Architecture Compliance Rules

- **ADR-0002:** hand-rolled parsers, no external crate. MUST NOT import any
  DNS-parsing library (trust-dns, nom-based DNS, etc.) in `mdns.rs`,
  `netbios.rs`, or `llmnr.rs`. Pure byte-slice arithmetic only.
- **ADR-0006:** hostnames entering `obs.hostnames` are scrubbed via the
  existing `name_NNN` class. No ADR-0006 amendment required. If the scrub
  layer ever adds a new code path that bypasses `obs.hostnames`, a new
  scrub-audit entry is needed — but this story does not do that.
- **Pure-core boundary:** `mdns.rs`, `netbios.rs`, `llmnr.rs` are pure
  functions (`&[u8] → output`). No I/O, no global state, no `unsafe`.
- **Forbidden dependencies:** the three new modules MUST NOT import
  `src/findings/*`, `src/inventory.rs`, `src/report*.rs`, or each other.
  Each parser is an independent recognizer.
- **Panic policy:** every parser must return `None` / empty `Vec` rather than
  panic on any malformed input. Property: `parse(&[])` and
  `parse(&[0xFFu8; 65535])` both return safely.
