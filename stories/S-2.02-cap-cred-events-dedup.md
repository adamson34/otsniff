# S-2.02: Cap `cred_events` by deduping at observation time

> **New BC introduced:** This story adds a new behavioral contract
> **BC-1.03.007 — `cred_events` are deduplicated at observation time
> by `(src, dst, dst_port, kind)`** to BC-INDEX (S.1 / S.1.03 section).
> The four pre-existing BCs (BC-1.03.001..004) describe credential
> *observation* and are unchanged; this story extends, not modifies,
> them. Mention the new BC in the BC-INDEX edit list for this story.

## Narrative

- **As an** analyst running otsniff on a long Telnet session capture
- **I want** memory usage proportional to unique (src, dst, port, kind)
  pairs, not raw packet count
- **So that** a 1M-packet capture doesn't push otsniff past memory pressure

## Acceptance Criteria

### AC-001 (traces to NFR-PERF.002 + existing BC-1.03.001..004 + new BC-1.03.007)
- **Step 1 — extract helper (refactor, non-behavioral):**
  No `Observer::record_cred_event` exists today. The four call sites
  are inline `self.obs.cred_events.push(...)` at `src/observe.rs:362,
  374, 387, 462`. Extract them into a private helper
  `fn record_cred_event(&mut self, event: CredEvent)`. This is a
  non-behavioral refactor — existing snapshot/unit tests stay green.
- **Step 2 — dedup inside helper (behavioral change):**
  The helper deduplicates by key `(src_ip, dst_ip, dst_port, kind)`
  instead of unconditionally pushing. A duplicate event increments a
  `count: u32` on the existing entry but does not append.
- **Test:** Property test ingests N synthetic FTP USER/PASS packets from
  the same `(src, dst)`; `cred_events.len() == 1`; `count == N`.

### AC-002 (no display regression)
- Per-finding rendering already deduplicates at report time today.
  After this story, the rendering layer reads the new `count` field
  for evidence display; output shape is unchanged.
- **Test:** Existing `tests/snapshot.rs` produces no diff for cred findings.

### AC-003 (memory regression test)
- A test ingests 1,000,000 synthetic Telnet packets from the same source;
  `cred_events.len() < 100` (allows for some legitimate variation across
  dst:port pairs); peak heap < 50 MB.
- **Test:** Heap measured via `cargo test --test memory_bound -- --nocapture`
  with a `Drop`-based allocator hook, OR test runs under `valgrind --tool=massif`
  in CI (see story tasks for which approach).

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | Same `(src,dst,port)` but different `kind` (e.g., FTP USER vs SNMP) | Distinct entries; counts independent |
| EC-002 | Single packet, no dup | `count == 1`, behaves identically to today |
| EC-003 | `count` overflows u32 (~4 billion) | Saturate at `u32::MAX`; do not panic |
