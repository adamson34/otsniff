# S-7.01: Zonewarden segmentation-conformance module (backfill)

> **BACKFILL RECORD** — This story did NOT go through the VSDD per-story
> pipeline. There is no red-gate log, no per-story adversarial review, and
> no holdout evaluation for this record. It exists to make the factory state
> match shipped reality. See `delivery_note` in frontmatter.

## Delivery summary

The standalone Zonewarden segmentation-conformance tool was folded into
otsniff as a named capability per ADR-0013. Delivered in PRs #123–#130
as part of the v0.5.0 release.

## What was delivered

### Core engine: `crates/zonewarden`

Pure Kani-verified engine imported from the standalone zonewarden repo
(history-preserved via `git filter-repo` subtree merge). The engine is a
workspace sub-crate — not a plain `src/` module — to preserve the enforced
pure-core guarantee (no I/O, no serde, no sockets in verified code).

Contains 7 Kani segmentation proofs: resolver correctness, classifier
determinism, IDMZ truth table, multicast exemption, tally arithmetic,
digest independence, and digest order-independence. ~96% mutation kill.

### Bridge + policy loader: `src/segmentation/`

- `src/segmentation/policy.rs` — YAML zone/conduit loader (effectful shell;
  serde lives here, not in the pure engine).
- Bridge function `observe::to_zonewarden_flows()` converts otsniff's native
  flow model into canonically-sorted Zonewarden `Flow` inputs (sorted so the
  deterministic `policy_digest` is reproducible despite non-deterministic
  PCAP parse order).

### Findings: `src/findings/zonewarden.rs`

Three new first-class findings:

| Finding ID | Severity | Description |
|---|---|---|
| `zonewarden.idmz_bypass` | Critical | OT↔IT flow with no DMZ hop |
| `zonewarden.wrong_direction` | High | Conduit matched but direction reversed |
| `zonewarden.deny_by_default` | High | No conduit permits this flow |

Egress dedup: when `--policy` is supplied, `egress.ot_to_internet` does not
fire for flows already owned by the Zonewarden engine — one finding per flow,
never duplicated.

### CLI surface

- `otsniff analyze PCAP --policy zones.yaml` — integrated path; Zonewarden
  section appears only when a policy is supplied (zero-config identity
  preserved).
- `otsniff zonewarden PCAP --policy zones.yaml` — focused segmentation-only
  path.
- `otsniff zonewarden suggest PCAP` — policy drafter; turns the asset
  inventory into a drafted `zones.yaml`.

### Report section

"Zonewarden — Segmentation Conformance" section (shown only when
`--policy` is supplied): Purdue-tiered topology diagram, conformance summary
(allowed / intra-zone / violations / bypasses), echoed zone/conduit policy,
deterministic `policy_digest` SHA-256 audit anchor.

### Formal verification (CI)

7 segmentation Kani harnesses added to `kani.yml` alongside the prior 4
privacy proofs (scrub round-trip, leak-detector regex, map-value substring,
composed privacy invariant).
