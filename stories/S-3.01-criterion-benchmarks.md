# S-3.01: Criterion benchmarks + hyperfine CI for perf regression detection

## Narrative

- **As a** maintainer about to refactor a hot path
- **I want** automated regression detection against a baseline
- **So that** a 2× slowdown can't ship silently

## Acceptance Criteria

### AC-001 (criterion microbenches)
- `benches/` directory exists with:
  - `parse_modbus.rs`, `parse_enip.rs`, `parse_s7comm.rs`, `parse_dhcp.rs`
  - `observe_pipeline.rs` (full ingest of a synthetic 10k-packet fixture)
  - `findings_run.rs` (run_all_findings against a fixed `Observations`)
- Each benchmark uses `criterion` and produces deterministic timing.
- **Test:** `cargo bench --bench parse_modbus -- --test` exits 0.

### AC-002 (hyperfine end-to-end)
- A CI job (separate from the main test job) runs `hyperfine
  --warmup 2 --runs 10 target/release/otsniff analyze tests/fixtures/synthetic-1mb.pcap -o /tmp/out.html`
  against a small synthetic fixture committed to the repo.
- Baseline timing is committed as a markdown table in `docs/PERF.md`.
- **Test:** CI job exists in `.github/workflows/perf.yml` and runs on schedule (weekly) plus on perf-labeled PRs.

### AC-003 (regression threshold)
- Workflow alerts (issues comment) but does not fail when `criterion`
  reports `change.regression: true` over the recorded baseline.
- Threshold for alert: 2× slower than baseline median (configurable per bench).

### AC-004 (memory-bound test)
- `tests/memory_bound.rs` (or feature-gated) ingests a synthetic
  Telnet-heavy fixture; asserts peak heap < 100 MB. Used to verify
  S-2.02's invariant continues to hold.
