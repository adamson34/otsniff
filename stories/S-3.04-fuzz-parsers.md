# S-3.04: Fuzz harnesses for all parsers

## Narrative

- **As a** maintainer treating PCAPs as untrusted input
- **I want** `cargo-fuzz` harnesses for every protocol parser
- **So that** crashes/UB on adversarial bytes are caught before users hit them

## Acceptance Criteria

### AC-001 (fuzz/ directory + harnesses)
- `fuzz/fuzz_targets/parse_modbus.rs`, `parse_enip.rs`,
  `parse_s7comm.rs`, `parse_dhcp.rs`, `parse_dnp3.rs` (if S-2.04 has
  merged), and `scrub_text.rs` exist.
- Each harness calls the corresponding `parse(payload: &[u8])` with
  fuzzer-provided input and asserts no panic.

### AC-002 (CI integration on slow schedule)
- `.github/workflows/fuzz.yml` runs each fuzz target for 60 seconds
  on weekly schedule.
- Discovered crashes upload as artifacts.

### AC-003 (corpus seeding)
- Each target seeds its corpus from `tests/fixtures/` raw payloads
  (if any) plus a minimal valid frame.

### AC-004 (regression mode)
- A `tests/fuzz_regressions.rs` test loads any `fuzz/artifacts/*/`
  reproducers and asserts the parsers handle them without panic.
- This stays green even when the fuzz CI workflow is paused.

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| Fuzz harnesses | `fuzz/fuzz_targets/` | tooling |
| Regression test | `tests/fuzz_regressions.rs` | test |
