# S-5.06: Apply the otsniff brand handoff — sniff-trail mark + ink/paper/accent palette + JetBrains Mono + inline favicon

## Narrative

- **As** the brand owner who shipped a brand handoff package (mark, palette, type, tone, iconography)
- **I want** the otsniff repo to use the actual brand mark and palette instead of the freehand approximations shipped in S-5.05
- **So that** every artifact otsniff produces — README, HTML report, future docs — reads as the same product, with one source of truth for color, type, and the brand mark

## Source of truth

The brand handoff package at `/Users/lukeadamson/Downloads/brand/` is the
spec. Specifically:
- `assets/otsniff-mark.svg` — primary mark, 64×64, `currentColor`
- `assets/otsniff-favicon.svg` — micro mark, 16×16, `currentColor`
- `README.md` §1–§9 — file inventory, mark construction math, palette,
  type, tone, iconography rules, application patches, verification

The handoff folder is **not committed**. The repo gets only the SVG
files (under `media/`, per project convention) and the README + template
edits that apply them.

### AC-002 (BC-8.01.004 — brand palette in :root)

The `<style>` block in `templates/report.html` defines exactly the
brand color tokens at `:root`:

- `--ink:    #15171c`
- `--paper:  #fbfaf6`
- `--accent: #ff7e35` (used SPARINGLY; max one accent element per
  visible screen per brand rule §3.3)
- `--ink-2:  #4a4639` (secondary text)
- `--muted:  #8a8474`
- `--line:   #c8c2ad`
- `--crit:   #c33a36`
- `--high:   #b87325`
- `--med:    #b59121`
- `--info:   #3c6da6`
- `--ok:     #2e7d4a`

The S-5.05-introduced tokens (`--bg-strong`, `--crit-soft`, `--high-soft`,
`--med-soft`, `--info-soft`, `--fg-on-dark`) are removed. Severity tints
become derived from the canonical hex by alpha-blending toward `--paper`
in CSS (`color-mix()` or a soft hex picked from § 3 supporting neutrals)
OR removed entirely in favor of just the left-border accent (cleaner;
matches brand handoff §7.2's instruction "keep those class names, just
update the hex values" — which suggests soft backgrounds aren't part of
the brand-mandated design).

The implementer chooses one of:
- (a) Soft tint per severity, derived from severity hex + paper via `color-mix(in oklch, var(--crit) 8%, var(--paper))`
- (b) No soft tint — finding cards stay on `--paper` background with only the 4px left border as severity affordance

Either is acceptable. Pick (a) for visual continuity with S-5.05; (b)
for purer brand adherence.

- **Test:** Substring asserts in rendered HTML — `--ink: #15171c`,
  `--paper: #fbfaf6`, `--accent: #ff7e35` all appear in the `<style>` block.

### AC-003 (BC-8.01.004 — JetBrains Mono type system)

The `<style>` block defines:

```css
--font-mono: "JetBrains Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
--font-sans: ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", Inter, Roboto, sans-serif;
```

`body` uses `--font-sans`. `h1, h2, h3, code, .mono` use `--font-mono`.
No external font load (the report is self-contained — JetBrains Mono is
in the stack but the fallback handles its absence).

- **Test:** Substring asserts for `--font-mono` AND `--font-sans` AND
  `"JetBrains Mono"` in the rendered HTML.

### AC-004 (BC-8.01.004 — sniff-trail mark in brand-header)

The current hero band (`<header class="hero">` from S-5.05) is REPLACED
by a `<header class="brand-header">` per brand handoff §7.2, containing:

- Inline SVG of the brand mark (copied byte-for-byte from
  `media/otsniff-mark.svg` body; `currentColor` so it adapts to theme)
- `.brand-wordmark` — "otsniff" + `<span class="brand-sep">·</span>` + "triage report"
- `.brand-meta` — `{{ input }} · v{{ version }} · {{ generated }}`
- Optional `.brand-chip` on the right showing capture-source + privacy
  state (omit if implementer judges the data isn't always available)

The 4 stat tiles (packets / bytes / hosts / findings) move OUT of the
hero band into a separate section below the header (S-5.05 had them
inside the hero — per brand handoff the header is the mark + wordmark
ONLY, with stats as their own component).

- **Test:** Substring asserts in rendered HTML — `class="brand-header"`,
  `class="brand-wordmark"`, `class="brand-meta"`, AND the rendered SVG
  contains exactly 7 `<circle` elements (1 hollow ring + 5 packet dots
  + 1 filled disc per brand handoff §2), 0 `<polyline` elements, 0
  `<path d=` elements (the freehand hexagon is gone).

### AC-005 (BC-8.01.004 — inline favicon as base64 data URL)

The `<head>` includes a `<link rel="icon" type="image/svg+xml" href="data:image/svg+xml;base64,...">`
where the base64 payload decodes to `otsniff-favicon-ink.svg` (the
ink-filled micro variant). Per brand handoff §8 — preserves the
"single self-contained file" invariant.

- **Test:** Substring asserts — `<link rel="icon"` AND
  `data:image/svg+xml;base64,` appear inside the `<head>` block. A
  sanity check decodes the base64 and asserts the result starts with
  `<svg` and contains `<circle cx="3.5"` (the hollow ring of the micro
  variant).

### AC-007 (BC-8.01.004 — snapshot diffs are structural only)

Following the same discipline as S-5.05, `cargo insta review` is used
to accept snapshot regen — NOT `INSTA_UPDATE=always`. Snapshot diffs
must be restricted to:
- Token values in the `:root` CSS block (color hexes, font tokens)
- The `<header>` markup region (brand-header replaces hero)
- The SVG markup inside the header (sniff-trail replaces hexagon)
- The `<link rel="icon">` line in `<head>`
- Class names and supporting CSS rules that flow from the above

NO data field (finding ID, IP, byte count, timestamp, packet count) may
change between develop and the post-S-5.06 tip.

- **Test:** The existing `render_html_snapshot_remains_data_stable`
  test from S-5.05 continues to pass.
