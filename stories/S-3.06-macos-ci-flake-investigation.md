# S-3.06: Stop the recurring macOS rustup-init/cargo flake in CI

## Narrative

- **As a** maintainer
- **I want** the macOS test job to pass reliably on first attempt
- **So that** every merge to develop and every PR doesn't cost us a 30-second rerun and a context switch

## Status (2026-05-14T14:50 update)

**Stopgap landed.** After a 3rd consecutive flake hit on the develop
push following PR #59 merge, the spec's option (a) — pin `runs-on:
macos-latest` → `runs-on: macos-14` — was applied as an immediate
stopgap in PR #60 (squash-merge SHA `547f644`). The first CI run
with `macos-14` passed cleanly on first attempt in 23 seconds. The
remaining S-3.06 work is:

- **AC-001 (investigation write-up):** Still pending — `docs/ci-investigations/2026-05-macos-rustup-flake.md` not yet authored.
- **AC-002 (5-consecutive-clean-runs verification gate):** First run green; need 4 more before this AC closes.
- **AC-003 (rollback plan):** Already documented in the PR #60 commit message; will be folded into the investigation note when AC-001 lands.

The story stays open in the v0.4.1-patch backlog. Status:
`pending → in_progress (stopgap landed; investigation + verification pending)`.

## Why now / why deferred

**Observed signal (updated 2026-05-14):** Hit 3× in 48 hours
(2026-05-13 on PR #58 CI; 2026-05-14 on the develop push after #58;
2026-05-14 on the develop push after #59 merge). Failure mode identical
all three times:

```
error: error: unexpected argument 'test' found
Usage: rustup-init[EXE] [OPTIONS]
```

`dtolnay/rust-toolchain@stable` successfully installs the toolchain
(`info: using existing install for stable-aarch64-apple-darwin`,
`info: default toolchain set to stable-aarch64-apple-darwin`) but the
next step's `cargo test` invocation resolves `cargo` → `rustup-init`
binary rather than the cargo proxy. Manual rerun clears it every time.

**Why deferred to v0.4.1-patch:** 30s rerun cost is below the bar for
interrupting Wave 1 detector work. Two hits is a pattern but not yet
an emergency — the build-out backlog (S-2.05..S-2.11 detectors) carries
more user value per point than CI surgery.

## Acceptance Criteria

### AC-001 (root-cause investigation, write-up)

- Investigation note committed under `docs/ci-investigations/2026-05-macos-rustup-flake.md`
  documenting:
  - Which `macos-latest` image versions were running at each flake
    occurrence (GitHub publishes the image label in the runner setup
    logs)
  - Whether the failure correlates with the runner image transition
    from macOS 14 → 15 (current hypothesis)
  - Whether other Rust projects on GitHub Actions have reported the
    same symptom (link upstream issues in dtolnay/rust-toolchain,
    actions/runner-images, or rust-lang/rustup if found)
- The note ends with a one-sentence root cause hypothesis and a
  recommended fix.

### AC-002 (apply chosen fix)

Pick exactly one of the following (justify in the investigation note):

- **(a) Pin runner image.** `runs-on: macos-latest` → `runs-on: macos-14`.
  Trade-off: pins to an older image; macos-14 is GA-supported until at
  least 2027 per GitHub's image lifecycle.
- **(b) Insert PATH/env normalization step.** Add a step between
  `dtolnay/rust-toolchain` and `cargo test` that runs
  `source "$HOME/.cargo/env" && which cargo && cargo --version` to
  force the cargo proxy into the shell's lookup path before invocation.
- **(c) Switch rust-toolchain action.** Replace `dtolnay/rust-toolchain@stable`
  with `actions-rust-lang/setup-rust-toolchain@v1` (the rust-lang
  org maintained alternative) if AC-001 finds an upstream fix landed
  in the newer action.

**Test:** After the fix lands, kick 5 consecutive CI runs on develop
(empty commits or workflow_dispatch). All 5 macOS jobs pass without
rerun. Document the run IDs in the investigation note.

### AC-003 (rollback plan)

If the chosen fix causes a different macOS regression, the investigation
note documents how to roll back (single-commit revert) and why the
next fallback option from the list above is the preferred next attempt.
