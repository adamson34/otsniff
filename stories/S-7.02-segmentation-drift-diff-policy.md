# S-7.02: Segmentation drift — `diff --policy` (backfill)

> **BACKFILL RECORD** — This story did NOT go through the VSDD per-story
> pipeline. There is no red-gate log, no per-story adversarial review, and
> no holdout evaluation for this record. It exists to make the factory state
> match shipped reality. See `delivery_note` in frontmatter.

## Delivery summary

Roadmap item P1-13. Composes the cross-capture diff (S-6.02 / S-6.03) and
Zonewarden conformance (S-7.01) into a single question: *did our
segmentation posture change between two captures of the same network?*
Delivered in PR #136 as part of the v0.5.0 release.

## What was delivered

An optional **segmentation-drift** computation added to the existing `diff`
subcommand, activated by `--policy PATH`. When a policy is supplied, the diff
runs the Zonewarden conformance engine against both captures and emits a
"Segmentation drift" section alongside existing host/finding/flow deltas.

### Data model additions (`src/diff.rs`)

- `DiffInput<'a>` gained `conformance: Option<&'a ConformanceResult>` field.
- `Diff` gained `segmentation: Option<SegmentationDrift>` (skipped in JSON
  when absent via `#[serde(skip_serializing_if = "Option::is_none")]`).
- New types: `SegmentationDrift` (policy_digest + tally + violation lists),
  `TallyDelta` (metric / baseline / current), `ViolationRef` (pseudonymized
  violation reference — the privacy-load-bearing type).

### Privacy invariant

`ViolationRef` pseudonymizes all endpoints via the merged scrub maps at
construction time using `resolve_ip_to_pseudonym`. The raw
`ConformanceResult` (which holds real IPs in `Violation` rows) is never
stored on `Diff` and never serialized — only the pseudonymized projection
reaches any output surface. Covered by a new invariant test asserting no
canary IPs escape to JSON, HTML, or markdown. The existing fail-closed leak
detector (`src/cli.rs`) applies as a backstop.

### Matching logic

Violations are matched across captures by the scrubbed key
`(kind, src_pseudonym, dst_pseudonym, dst_port, proto)` — mirroring
`finding_diff_key`. `flow_index` is explicitly NOT a match key (it is a
dense index per capture, not stable across captures).

### CLI surface

`otsniff diff baseline.pcap current.pcap --policy zones.yaml -o drift.html`

One policy, held constant: both captures are scored against the same policy
so tallies are attributable solely to traffic changes, not policy revisions.
No `--baseline-policy`/`--current-policy` surface.

### Output

- **HTML**: "Segmentation drift" section (only when `Diff.segmentation`
  present): policy anchor line (muted, records `policy_digest`), tally
  table (metric / baseline / current / ▲▼— direction-tinted), violation
  deltas (new / resolved / persisting per-flow rows with pseudonyms).
- **Markdown**: mirror of HTML section, `## Segmentation drift`, tally
  table, violation-delta lists. Deterministic sort.
- **JSON**: `Diff.segmentation` serializes natively; key absent when no
  `--policy`.

### Determinism

Violation output vectors sorted by `(kind, src_pseudonym, dst_pseudonym,
dst_port, proto)` before return; tally in fixed metric order. Same
discipline as existing diff vectors.
