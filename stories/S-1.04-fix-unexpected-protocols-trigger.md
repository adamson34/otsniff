# S-1.04: Fix `ot.unexpected_protocols` trigger description vs code drift

## Narrative

- **As an** OT defender reading the rule catalog or a finding's
  "Detection criteria" line
- **I want to** see a trigger description that lists every port label
  the detector actually checks
- **So that** I can verify what fired and explain it to engineering

## Acceptance Criteria

### AC-001 (traces to BC-3.05.002, fixing L-P0-001)
- `src/findings/unexpected_protocols.rs::METADATA.trigger` lists all 11
  labels currently returned by `unexpected_label()`: `anydesk, apns,
  bittorrent, gcm, irc, openvpn, rtmp, sip, smtp, stun, teamviewer`.
- The zone predicate in `METADATA.trigger` reads "src OR dst in OT
  zone," not "src in OT AND dst not in OT".
- **Test:** Unit test asserts `METADATA.trigger` contains all 11 label
  strings, fails the build if drift recurs.

### AC-002 (auto-generated RULES.md regenerates clean)
- After the trigger string is fixed, running `cargo run -- rules > docs/RULES.md`
  produces a diff-clean RULES.md.
- The committed `rule_catalog_matches_committed_rules_md` snapshot test
  passes against the new RULES.md.
- **Test:** CI on this story's branch shows `rule_catalog_matches_committed_rules_md` green.

### AC-003 (no behavior change)
- The detector firing logic is unchanged. The 11 ports the detector
  flags today still fire; no port is added or removed.
- **Test:** Existing snapshot tests in `tests/snapshot.rs` produce no diff.
