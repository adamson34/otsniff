# S-1.05: Promote 15 BC-AUDIT items into first-class BCs

## Narrative

- **As a** spec maintainer planning the next mutation-test or fuzz pass
- **I want to** see the 15 audit-derived behaviors expressed as
  first-class BCs in the PRD §5 + BC-INDEX
- **So that** load-bearing module behaviors (OUI lookup, MAC format,
  exit-code mapping, DHCP option walk bounds, S7 ROSCTR sizing, evidence
  caps, prompt sparse-capture refusal, ClaudeCli PATH check, report_md
  ordering) have addressable spec rows

## Acceptance Criteria

### AC-001 (each audit row becomes a numbered BC)
- BC-AUDIT-001..015 are each rewritten as a `BC-{subsystem}.{group}.{idx}`
  row in the PRD §5 BC catalog, mapped per the BC-INDEX subsystem
  taxonomy (S.0..S.9).
- The new BC IDs are appended, not renumbered over existing rows.
- Suggested mapping (story may revise if the audit's wording demands
  different placement):
  - BC-AUDIT-001 → BC-2.02.001 (OUI prefix-exact lookup)
  - BC-AUDIT-002 → BC-5.01.004 (format_mac upper-hex colon for leak-detector match)
  - BC-AUDIT-003 → BC-0.02.001 (OtError variant-to-exit-code completeness)
  - BC-AUDIT-004 → BC-0.02.002 (OtError chain-of-sources printing)
  - BC-AUDIT-005 → BC-1.02.005 (DHCP option walk bounded)
  - BC-AUDIT-006 → BC-1.02.006 (DHCP 3-tier IP resolution)
  - BC-AUDIT-007 → BC-1.02.007 (S7 ROSCTR-driven header sizing)
  - BC-AUDIT-008 → BC-3.06.005 (evidence cap default 15, with exceptions enumerated)
  - BC-AUDIT-009 → BC-3.05.003 (unexpected_label port-to-label table)
  - BC-AUDIT-010 → BC-3.02.002 (internet_egress playbook branches on flow categories)
  - BC-AUDIT-011 → BC-3.04.003 (stale_tls is_stale range 0x0300..=0x0302)
  - BC-AUDIT-012 → BC-3.03.004 (engineering_commands roll-up by (src,dst))
  - BC-AUDIT-013 → BC-6.02.002 (sparse-capture refusal branch in prompts)
  - BC-AUDIT-014 → BC-6.03.002 (ClaudeCliProvider PATH pre-check)
  - BC-AUDIT-015 → BC-8.01.002 (report_md top-level structure ordering)
- **Tests:**
  - Each new BC ID listed in the mapping table (BC-2.02.001, BC-5.01.004,
    BC-0.02.001, BC-0.02.002, BC-1.02.005, BC-1.02.006, BC-1.02.007,
    BC-3.06.005, BC-3.05.003, BC-3.02.002, BC-3.04.003, BC-3.03.004,
    BC-6.02.002, BC-6.03.002, BC-8.01.002) appears as a first-class
    row in BC-INDEX under the right subsystem section.
  - Pre-migration `grep -c '^- BC-AUDIT-' BC-INDEX.md` == 15.
  - Post-migration `grep -c '^- BC-AUDIT-' BC-INDEX.md` == 0 outside
    the legacy alias table.
  - Both counts run as part of the story's smoke check.

### AC-002 (BC-AUDIT-* IDs retained as legacy aliases)
- BC-INDEX retains a "Legacy audit-IDs" alias table mapping each old
  BC-AUDIT-NNN to its new BC-S.SS.NNN form. Existing references in
  Phase 0/1 docs survive without rewriting.

### AC-003 (PRD § coverage)
- Each new BC has at least one PRD §3 functional-requirement row or
  §6 NFR row that cites it, even if it's a one-liner.
