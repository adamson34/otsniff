# S-3.05: Wire codecov coverage reporting into CI + add badge

## Narrative

- **As a** maintainer evaluating which subsystems are under-tested
- **I want** per-PR coverage reports uploaded to codecov.io
- **So that** the next test-writer dispatch can target uncovered code
  and the README can show a meaningful coverage badge that resolves

## Why now / why deferred

Surfaced during the v0.4 README rewrite (PR #53) when the user asked
about the codecov badge row matching the `jr` CLI pattern. The badge
was dropped from #53 because the upstream coverage CI wasn't wired —
a badge that points to nothing would be misleading.

Filed to track the work; **execution deferred** until the user opts
in. Will likely ship as part of the v0.4.1 patch alongside S-2.12
(recon rollup) so the v0.4.1 release notes can announce both
"recon.port_scan over-fire fixed" and "coverage reporting live."

## Acceptance Criteria

### AC-001 (BC-build.001 — coverage runs on every PR + push)

`.github/workflows/ci.yml` gains a `coverage` job that:

- Runs on `ubuntu-latest`
- Installs `cargo-llvm-cov` (preferred over `cargo-tarpaulin` —
  llvm-cov is more accurate on Rust and the install is `cargo install
  cargo-llvm-cov --locked` plus the `llvm-tools-preview` rustup
  component)
- Runs `cargo llvm-cov --all-features --workspace --lcov --output-path lcov.info`
- Uploads `lcov.info` to codecov via `codecov/codecov-action@v4`

The job runs on `pull_request` and `push: branches: [main, develop]`
events — same triggers as the existing jobs.

- **Test:** `.github/workflows/ci.yml` contains a `coverage` job with
  the `codecov/codecov-action@v4` step. (Structural test against the
  YAML file's text.)

### AC-002 (BC-build.001 — tokenless upload for public repo)

The codecov action runs **without a `CODECOV_TOKEN` secret** — public
GitHub repos support tokenless upload via OIDC. No new repo secret
to manage; no rotation surface.

- **Test:** The `codecov/codecov-action@v4` step in the YAML has NO
  `token:` input. (Structural assertion: grep the workflow for
  `token:` near the codecov step.)

### AC-003 (BC-build.001 — codecov.yml config sets baseline targets)

A new `codecov.yml` at repo root configures:

```yaml
coverage:
  status:
    project:
      default:
        target: auto         # against previous coverage
        threshold: 1%        # allow 1% drop without failing
    patch:
      default:
        target: 70%          # new code must be 70% covered
        threshold: 0%        # no slop on the patch
comment:
  layout: "reach, diff, flags, files"
  behavior: default
  require_changes: true      # only comment on PRs that change coverage
ignore:
  - "tests/**"
  - "benches/**"
  - "fuzz/**"
  - "build.rs"
```

Targets are conservative; can tighten once a baseline lands. The
`ignore` list prevents tests/benches from counting against coverage.

- **Test:** `codecov.yml` exists and contains the `coverage.status`,
  `comment`, and `ignore` keys.

### AC-004 (BC-build.001 — README badge added in the existing badge row)

The badge row in `README.md` gains a codecov badge between MSRV and
the end of the row:

```html
<a href="https://codecov.io/gh/adamson34/otsniff"><img src="https://codecov.io/gh/adamson34/otsniff/graph/badge.svg" alt="codecov"></a>
```

- **Test:** `README.md` contains the substring `codecov.io/gh/adamson34/otsniff`.

### AC-005 (no regression in existing CI gates)

The 7 existing CI checks (Format, Clippy, Test ubuntu, Test macos,
MSRV, POL-12, cargo-deny) continue to pass. The coverage job is
additive — it doesn't replace anything.

- **Test:** Existing `cargo test`, `cargo clippy`, `cargo fmt --check`
  all pass after the changes.

### AC-006 (coverage badge resolves)

After merge, the codecov.io badge URL returns a real coverage number,
not "unknown" or "404". (Manual verification post-merge; not a CI
test.)

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | Coverage upload fails (codecov API down) | Job fails — clear signal in PR. Trade-off: codecov outages will fail CI. Accept; codecov has good uptime. |
| EC-002 | A PR drops coverage by > 1% | codecov posts a status check "project/default" → failure. The codecov status check is configured as informational (not required by branch protection), so the PR can still merge if the drop is intentional. |
| EC-003 | A PR adds < 70% covered patch | codecov posts "patch/default" failure. Same treatment — informational. |
| EC-004 | Snapshot tests inflate coverage artificially | The `ignore: tests/**` prevents that. Coverage measures `src/` only. |
| EC-005 | `cargo-llvm-cov` install time slow | Install is cached via `Swatinem/rust-cache@v2`. First CI run is ~3 min; subsequent runs <30s. |

## Constraints

- **No `Co-Authored-By: Claude` trailer on any commit.**
- **No absolute paths** — POL-12 lint enforces.
- **No new runtime dependencies.** `cargo-llvm-cov` is a CI-only dev tool.
- **No secrets management.** Use tokenless upload (public repo OIDC).
- **Coverage targets stay conservative initially.** The first PR after
  this lands will set the baseline; tightening can come later as a
  spec evolution (no immediate need for high targets — the value is
  the trend, not the absolute number).
