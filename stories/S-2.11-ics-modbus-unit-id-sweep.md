# S-2.11: `ics.modbus_unit_id_sweep` — Modbus unit-id discovery

## Narrative

- **As an** OT defender spotting Modbus reconnaissance
- **I want** otsniff to flag a Modbus client that issues requests to
  ≥ N distinct unit IDs against the same target server within the capture
- **So that** PLC discovery / fuzzing patterns surface

## Acceptance Criteria

### AC-001 (BC-1.02.006 — unit-id tracking)
- `observe.rs` extends Modbus event tracking to record unit IDs seen
  per `(src, dst)` pair (was function-code-only).
- New field `ModbusFlowSummary { unit_ids: BTreeSet<u8>, ... }` keyed
  by `(src, dst)` in `Observations`.
- **Test:** Unit test asserts unit IDs accumulate correctly.

### AC-002 (BC-3.03.006 — sweep detection)
- `src/findings/modbus_recon.rs` fires `ics.modbus_unit_id_sweep` at
  severity Medium when `unit_ids.len() >= 5` for any `(src, dst)` pair.
- Severity escalates to High at ≥ 50 distinct unit IDs.
- Evidence lists `(src, dst)` and the unit-id count + first 10 IDs.
- **Test:** Snapshot test with fixture of 1 src → 1 dst with 10 unit IDs.
