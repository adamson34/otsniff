# S-5.02: Claude invocation heartbeat — "[Ns] still working..." every ~3s

## Narrative

- **As a** user with `--ai` enabled
- **I want** periodic stderr heartbeats while otsniff waits on `claude`
- **So that** I can tell the process is alive during a 60-second LLM call

## Acceptance Criteria

### AC-001 (BC-6.04.001 — heartbeat cadence)
- `ClaudeCliProvider::analyze` spawns the `claude -p` subprocess on a
  background thread.
- The main thread emits `[Ns] still working...` to stderr every 3
  seconds while the subprocess is alive.
- On completion: `done in 11.4s, 4127 bytes response`.
- **Test:** Inject a sleeping mock subprocess (test helper); assert ≥ 3
  heartbeats over 10 simulated seconds, plus the final summary.

### AC-002 (no heartbeat if subprocess returns in < 3s)
- If the subprocess completes before the first heartbeat would fire,
  only the summary line is emitted.

### AC-003 (no behavior change on response)
- The unscrub-and-render pipeline still operates on the full response
  byte buffer (no mid-stream display per ADR-0007 privacy contract).

### AC-004 (silent in non-verbose mode)
- Heartbeats only emit when `-v` is set OR when stderr is a TTY.
  Document the choice in source comments.
