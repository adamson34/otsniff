# S-5.04: Harden `--ai` invocation surface — disallow Claude Code tools + opt-in scrub review

## Narrative

- **As a** compliance-conscious analyst running `otsniff analyze --ai`
- **I want** the spawned `claude -p` subprocess to be tool-sandboxed AND
  the option to eyeball the scrubbed prompt before it goes out
- **So that** the privacy claim isn't defeated by claude reading the
  source PCAP itself (Bash/Read tools) or by a leak detector bug

## Threat model context

The scrub layer + leak detector enforce "no real identifier appears in
the bytes piped to claude's stdin." But `claude -p` is a full Claude
Code instance with default tool access (Bash, Read, Write, WebFetch,
Glob, Grep, etc.). Nothing prevents the LLM from running
`cat <pcap_path>` or reading `<report>.map.json` (which holds the
pseudonym ↔ real mapping in plaintext).

ADR-0007 ("AI via Claude Code CLI") did not address this — it covered
the marketing win (no API key in otsniff's env, no HTTP client) but
not the runtime tool-sandbox question. ADR-0006 (scrub/unscrub) covers
prompt-byte sanitization but not what claude can fetch with its own
tools while running.

This story closes both gaps:
1. Always pass `--disallowed-tools` to remove the tool exfiltration path.
2. Add a `--review-scrub` flag so a paranoid operator can manually
   eyeball the scrubbed bytes before they are sent.

## Acceptance Criteria

### AC-001 (BC-6.03.002 — Claude invocation passes `--disallowed-tools`)

- `src/ai/claude_cli.rs::ClaudeCliProvider::analyze` ALWAYS includes
  `--disallowed-tools` in the spawned command's args, listing every
  Claude Code tool that can read the filesystem or reach the network:
  `Bash Read Write Edit WebFetch WebSearch Glob Grep Task NotebookEdit`.
  Exact tool list lives in a `const DISALLOWED_TOOLS` so future Claude
  Code releases can be tracked.
- The flag is NOT user-configurable. It is a defense, not a knob.
- **Test:** A unit test in `src/ai/claude_cli.rs::tests` constructs
  the `Command` (don't spawn it) and asserts the args contain
  `["--disallowed-tools", "Bash,Read,Write,Edit,WebFetch,WebSearch,Glob,Grep,Task,NotebookEdit"]`
  (or whatever delimiter format the CLI expects — check Claude Code's
  current syntax; if it uses repeated `--disallowed-tools` flags
  instead of comma-separated, the test reflects that).

### AC-002 (BC-9.06.001 — `--review-scrub` opt-in pause)

- `analyze` subcommand accepts a `--review-scrub` flag. When NOT set,
  current flow is preserved (default = no interactive pause).
- When SET, after scrub + leak-detector clean and BEFORE invoking
  claude:
  1. Otsniff writes the scrubbed bytes to stderr prefixed by a header
     `--- scrubbed prompt to claude ({N} bytes) ---` and footer
     `--- end scrubbed prompt ---`.
  2. Otsniff reads a single line from stdin with prompt
     `Send to claude? [y/N]: `.
  3. If stdin trimmed-and-lowercased is exactly `y` or `yes`, proceed.
     Anything else (including EOF) → `OtError::Parse("aborted by --review-scrub")`
     → exit code 70.
- **Test 1:** Smoke test pipes `n\n` to stdin with `--review-scrub` →
  exit code 70 + stderr contains the scrubbed-prompt header.
- **Test 2:** Smoke test pipes `y\n` to stdin with `--review-scrub` →
  flow proceeds (mock provider replaces claude so test is hermetic).
- **Test 3:** Smoke test without `--review-scrub` → no header on
  stderr, no stdin read attempted, claude invoked directly. (Existing
  behavior preserved.)

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | Future Claude Code release adds a new tool not in DISALLOWED_TOOLS | Tool would be allowed by default — flag this in the `DISALLOWED_TOOLS` comment with a "review-when-claude-updates" note. Run `claude --help` on each toolchain refresh. |
| EC-002 | User runs with `--review-scrub` but stderr is redirected to /dev/null | Header still emitted (just not visible). The stdin prompt still appears (since the prompt prints to stderr too). User-visible behavior: appears to hang on stdin. Document as "if you redirect stderr, you can't see the prompt." |
| EC-003 | User pipes `--review-scrub` with closed stdin (e.g., `< /dev/null`) | EOF on stdin → treated as "anything but y" → abort with exit 70. |
| EC-004 | Claude Code CLI's `--disallowed-tools` syntax differs from what we assume | Detect at runtime: if `claude --help` does not document `--disallowed-tools`, the flag is silently rejected by claude and tools are NOT actually disabled. Mitigation: a sentinel `which_claude` check now also reads `claude --help` once on startup and warns if `--disallowed-tools` is absent. (Stretch; if the implementer judges it scope creep, log as a follow-up roadmap entry instead.) |
