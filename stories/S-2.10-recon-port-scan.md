# S-2.10: `recon.port_scan` — same src to many dst on same port

## Narrative

- **As an** OT defender wanting to spot reconnaissance traffic
- **I want** otsniff to flag a source IP that talks to ≥ N distinct
  destination IPs on the same destination port within the capture
- **So that** port-scan and host-discovery patterns surface in the report

## Acceptance Criteria

### AC-001 (BC-1.05.004 + BC-3.05.005)
- New detector iterates over `Observations::flows`, groups by
  `(src_ip, dst_port, proto)`, counts distinct `dst_ip`.
- Fires `recon.port_scan` at severity Medium when count ≥ 5 distinct dsts.
- Threshold is `const PORT_SCAN_THRESHOLD: usize = 5` for now; comment
  it as tunable.
- Severity escalates to High when count ≥ 25.
- Evidence: per src+port, list (up to 15) dst IPs and count.
- **Test:** Snapshot test with fixture: 1 src to 10 dsts on tcp/445 →
  one finding at Medium.

### AC-002 (asymmetric flows handled)
- Detector counts only flows where dst is the "responder" / "passive"
  side, matching the existing flow keying. Replies from each dst back
  to src are not double-counted.

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|

| EC-004 | Single src to many dsts on different ports | Not flagged (this finding is per-port) |
