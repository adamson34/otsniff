# S-2.05: `creds.ldap_simple_bind` — LDAP plaintext bind detection

## Narrative

- **As an** OT defender on a network where small IT shops still ship
  default Windows AD without LDAPS
- **I want** otsniff to flag LDAP `BindRequest` with `SimpleAuthentication`
  on plaintext tcp/389
- **So that** the report calls out a real credentials-in-cleartext
  exposure that the existing `creds.*` family otherwise misses

## Acceptance Criteria

### AC-001 (BC-1.03.005 — LDAP simple-bind observation)
- `observe.rs` recognizes BER-encoded LDAP `BindRequest` (tag 0x30
  envelope + ProtocolOp tag 0x60) on tcp/389 with version 3 and
  `SimpleAuthentication` choice (tag 0x80).
- Emits `LdapBindEvent { src, dst, dst_port, version, used_starttls: bool }`.
- **Test:** Round-trip test with raw byte fixture of a real BindRequest.

### AC-002 (BC-3.01.005 — finding emission)
- `creds.ldap_simple_bind` fires at severity Critical when an
  `LdapBindEvent` is observed without prior STARTTLS on the same flow.
- Rolls up by `(src, dst)` like the other `creds.*` findings.
- **Test:** Snapshot test with synthetic fixture.

### AC-003 (STARTTLS suppression — paired control test)
- If the same flow shows a successful LDAP STARTTLS exchange before
  the BindRequest, the finding does NOT fire.
- **Tests (paired, must share the same base fixture):**
  - **Positive:** `BindRequest` alone → exactly one
    `creds.ldap_simple_bind` finding fires.
  - **Negative:** the same `BindRequest` preceded by a successful
    STARTTLS exchange → zero `creds.ldap_simple_bind` findings.
  - Both tests must live in the same module so a future regression
    that breaks the suppression logic flips the negative test from
    pass to fail (the vacuous-pass case is impossible because the
    positive test confirms the firing path works).

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
