# S-3.02: Prompt evaluation harness with rubric-based comparison

## Narrative

- **As a** maintainer tuning the Claude system prompt
- **I want** a committed set of (Observations fixture, expected-shape rubric)
  evals that I can run against the current `claude` CLI
- **So that** prompt regressions surface before users notice

## Acceptance Criteria

### AC-001 (rubric format)
- `tests/prompt-evals/` directory contains at least 4 evals:
  - One per capture-source variant (SPAN, host-side, TAP, ambiguous)
  - Each eval is a directory with `observations.json` (scrubbed),
    `rubric.md` (expected behavior shape), and `run.sh` (invocation).
- Rubric format: numbered must/should assertions. Examples:
  - "MUST contain a Priority-1 reference to host_001"
  - "SHOULD qualify topology claims when capture_source is host-side"
  - "MUST NOT mention any IP/MAC/hostname in real form"

### AC-002 (runner)
- `cargo xtask eval-prompts` (or a `tests/prompt-evals/run_all.sh`)
  invokes the local `claude` CLI for each eval, captures response,
  scores against rubric using lightweight pattern matching, prints
  pass/fail per eval.
- The leak-detector runs on every captured response (sentinel test
  invariant must hold for prompt-eval responses too).
- **Test:** `tests/prompt_evals.rs` invokes the runner in `--dry-run`
  mode (no actual claude CLI calls) and asserts the runner parses
  rubric files without error.

### AC-003 (non-flake handling)
- Rubric assertions are pattern-based, not exact-string. LLM
  non-determinism is expected. A `pass` requires ≥ 90% of MUST
  assertions met across 3 runs.
- **Test:** Documented in `tests/prompt-evals/README.md`.

### AC-004 (CI integration is opt-in)
- The eval harness is not run in PR CI by default (cost + flake).
- A manual workflow_dispatch in `.github/workflows/prompt-evals.yml`
  runs the harness against the merged develop tip when triggered.

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| Eval fixtures | `tests/prompt-evals/*/observations.json` | data |
| Runner | `tests/prompt-evals/run_all.sh` or `xtask` | effectful-shell |
| Rubric parser | (test helper) | pure-core |

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | `claude` CLI not installed | Runner exits with explanatory error, no fail |
| EC-002 | Eval response contains real IP | Leak detector trips, eval marked FAIL with explicit message |
| EC-003 | LLM produces a brand-new but valid analysis shape | Rubric SHOULD assertions may fail; document escape valve |
