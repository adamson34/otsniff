# S-4.03: Kani proof — `ensure_no_map_values` substring invariant

## Narrative

- **As a** compliance reviewer
- **I want** a proof that `ensure_no_map_values` returns `Err` iff any
  value in the map appears as a substring of the input
- **So that** hostname-shape leaks (which the regex cannot catch)
  cannot pass the kill switch

## Acceptance Criteria

### AC-001 (BC-5.02.002 proven)
- `kani-proofs/ensure_no_map_values.rs` proves bidirectional invariant:
  - If any `v ∈ map.real_values()` appears as a substring of `input`,
    the function returns `Err`.
  - If no `v ∈ map.real_values()` appears as a substring of `input`,
    the function returns `Ok`.
- Bounds: input length ≤ 32, ≤ 4 map values each ≤ 8 bytes. Document choice.
- **Test:** `cargo kani --harness map_value_substring` proves.
