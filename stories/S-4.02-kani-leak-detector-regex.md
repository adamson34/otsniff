# S-4.02: Kani proof — leak detector regex matches every IPv4/IPv6/MAC-shaped substring

## Narrative

- **As a** compliance reviewer
- **I want** a proof that the leak-detector regex saturates every
  IPv4-shaped substring (and equivalently IPv6 and MAC)
- **So that** the kill-switch's primary defense isn't an implicit "I'm pretty sure"

## Acceptance Criteria

### AC-001 (BC-5.02.001 proven)
- `kani-proofs/leak_detector_regex.rs` proves: for every byte string
  `s` of length ≤ N that contains a substring of the shape
  `(\d{1,3}\.){3}\d{1,3}` with all components < 256, the leak detector
  regex matches.
- Similar harness for IPv6 (shorter coverage acceptable; document)
  and MAC `XX:XX:XX:XX:XX:XX`.
- **Test:** `cargo kani --harness leak_regex_ipv4` proves.

### AC-002 (false-negative test included)
- The proof's failure case is a real bug, not just a Kani limitation.
- The harness explicitly tries adversarial shapes (e.g., embedded in
  log-prefix, surrounded by punctuation) and they all match.
