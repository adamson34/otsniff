# S-2.07: `compat.weak_tls_cipher` — TLS ClientHello with RC4/DES/3DES/NULL

## Narrative

- **As an** OT defender looking at TLS hygiene
- **I want** otsniff to flag ClientHellos that advertise RC4, DES, 3DES,
  or NULL cipher suites, even if the negotiated TLS version is modern
- **So that** weak-cipher capability is visible alongside the existing
  `compat.stale_tls` finding

## Acceptance Criteria

### AC-001 (BC-1.04.003 — TLS cipher list observation)
- The TLS ClientHello observer in `observe.rs` (currently capturing
  `legacy_version` for `compat.stale_tls`) is extended to capture
  the cipher_suites list.
- A new `TlsHelloEvent::cipher_suites: Vec<u16>` field is added (or
  reuse / rename existing event struct).
- **Test:** Round-trip test with a captured ClientHello payload asserts
  cipher_suites parsed correctly.

### AC-002 (BC-3.04.005 — finding emission)
- `compat.weak_tls_cipher` fires at severity Medium when any of the
  following appears in `cipher_suites`:
  - TLS_RSA_WITH_RC4_128_MD5 (0x0004), TLS_RSA_WITH_RC4_128_SHA (0x0005)
  - TLS_RSA_WITH_DES_CBC_SHA (0x0009), TLS_RSA_WITH_3DES_EDE_CBC_SHA (0x000A)
  - TLS_RSA_WITH_NULL_MD5 (0x0001), TLS_RSA_WITH_NULL_SHA (0x0002)
  - (Full list documented in the detector source)
- Rolls up by `(src, dst)` listing the offending cipher suite codes.
- **Test:** Snapshot test with synthetic fixture.

### AC-003 (parallel to stale_tls, not duplicate)
- A ClientHello with both legacy_version AND weak cipher fires
  both findings. They are sibling findings, not exclusive.
