# S-5.07: Make each finding card individually collapsible

## Narrative

- **As an** analyst reading a report with 15+ findings
- **I want** to collapse the finding cards I've already triaged so the
  ones I haven't are easier to scan
- **So that** long-finding reports (4SICS-22 type captures with a dozen
  findings) stay navigable instead of becoming a wall of expanded cards

## Context

Today (post-S-5.06) the report has:
- Asset inventory section: collapsible via `<details open class="table-section">` (S-5.05 AC-007)
- Top flows section: collapsible (S-5.05 AC-007)
- AI section: NOT collapsible (deliberate; brand handoff §6 keeps the
  AI rail prominent)
- Findings section: NOT collapsible at the section level; each finding
  card has nested `<details>` for evidence + criteria + playbook, but
  the whole card is always expanded

This story makes each finding card itself collapsible at the card
level — independent of the existing nested `<details>` inside it.

## Acceptance Criteria

### AC-001 (BC-8.01.005 — outer card is `<details open>`)

Each finding card in `templates/report.html` is wrapped in
`<details open class="finding sev-{{ f.severity_class }}">` instead of
the current `<div class="finding sev-...">`. The first child is a
`<summary>` containing the existing `.finding-head` content (severity
badge + title).

- **Test:** A unit test asserts the rendered HTML contains
  `<details open class="finding sev-` at least once (assuming any
  finding fires in the fixture) and the count of top-level
  `class="finding ` matches the count of `<details open class="finding `.

### AC-002 (BC-8.01.005 — summary shows severity + title, NOT just a chevron)

The `<summary>` element retains the existing visual treatment of the
finding head: severity badge as a pill, title in JetBrains Mono. The
default browser triangle marker is suppressed via
`details.finding > summary::-webkit-details-marker { display: none; }`
and a `▾ / ▸` chevron is rendered via `::before` per the existing
section-summary pattern.

The summary is the ENTIRE clickable area — clicking anywhere on the
severity badge, the title, or the area beside them toggles the card
open/closed.

- **Test:** The rendered HTML contains
  `details.finding > summary::-webkit-details-marker { display: none; }`
  (or a `summary` element with the brand chevron `▾`).

### AC-003 (BC-8.01.005 — default state is open)

All finding cards render `<details open ...>` so the first impression
is the existing behavior. The user can collapse any card they've
already read; nothing collapses by default.

- **Test:** Rendered HTML has zero `<details class="finding"` without
  the `open` attribute (i.e., 0 closed-by-default finding cards).

### AC-004 (BC-8.01.005 — nested `<details>` for evidence/criteria/playbook still work)

The existing `<details>` for evidence, detection criteria, and
playbook MUST remain functional inside the new outer `<details>`. CSS
nesting and chevron-rendering rules must be scoped so the outer
chevron and inner chevrons don't visually conflict.

- **Test:** Rendered HTML still contains at least one nested
  `<details><summary>Evidence` (inside a `<details class="finding">`)
  AND at least one nested `<details open><summary>Investigation
  playbook` (the playbook stays default-open per S-5.05's pattern).

### AC-005 (BC-8.01.005 — print preserves expanded state)

Inside `@media print`, force all finding-level `<details>` to render
their content regardless of user state. Mirror the existing pattern
established for `.table-section`:

```css
details.finding > *:not(summary) { display: block !important; }
details.finding > summary::-webkit-details-marker,
details.finding > summary::before { display: none !important; content: "" !important; }
```

- **Test:** Rendered HTML contains a print-mode override targeting
  `details.finding`.

### AC-006 (data-shape stability guard — same as S-5.05/5.06 AC)

The existing `render_html_snapshot_remains_data_stable` test
continues to pass. No finding ID, IP, byte count, packet count, or
timestamp changes between develop and the post-S-5.07 tip.

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | Report has zero findings | The "No findings raised" callout stays unchanged — only the cards inside the findings list become collapsible. |
| EC-002 | User has JavaScript disabled | `<details>` is pure HTML; works without JS. No change. |
| EC-003 | User prints with Cmd-P | All finding cards render fully expanded per AC-005. |
| EC-004 | Severity badge click vs. title click | Both toggle the card (the entire `<summary>` is the trigger). |
| EC-005 | Mobile / narrow viewport | `<details>` triangle button is always tappable; existing flex layout keeps the summary single-line. |
