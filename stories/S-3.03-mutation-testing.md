# S-3.03: Wire `cargo-mutants` against `src/` with triage rules

## Narrative

- **As a** maintainer who wants confidence that tests are doing real work
- **I want** mutation testing to identify dead/weak tests
- **So that** we can fix coverage gaps before they bite

## Acceptance Criteria

### AC-001 (cargo-mutants installed + scoped)
- `.cargo-mutants.toml` exists at repo root.
- Mutants are run only against `src/findings/`, `src/parse/`,
  `src/scrub.rs`, `src/ai/leak_detector.rs` initially (high-value modules).
- Skip-list documented for known-irrelevant mutations.

### AC-002 (CI integration on slow schedule)
- `.github/workflows/mutants.yml` runs weekly on develop tip.
- Reports kill-rate to an issue comment / artifact.
- Does not block PRs.

### AC-003 (kill-rate baseline + ratchet)
- Initial baseline kill-rate is recorded in `docs/MUTANTS.md`.
- A future PR that drops kill-rate by > 5% is flagged for review (soft signal).

### AC-004 (triage doc)
- `docs/MUTANTS.md` documents:
  - Why these modules are in scope
  - How to interpret a "missed" mutation
  - Common false-positives in this codebase (e.g., metadata strings,
    log levels, evidence sample order)
