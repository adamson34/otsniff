## Evaluation Notes / Findings Resolved

Running HS-006 surfaced and fixed three latent issues (none a product defect in
the parsers/scrub logic):

1. **cargo-fuzz install broken in CI** — `fuzz.yml` used unpinned `@nightly`;
   cargo-fuzz's `rustix` dep stopped compiling on bleeding-edge nightly, so the
   fuzzers never ran. Fixed by pinning `nightly-2025-11-21` + `cargo-fuzz =0.13.1`
   (PR #109). Same toolchain-churn class as S-3.06.
2. **scrub_text fuzz target didn't compile** — referenced `chrono` without a
   direct dep (masked because the workflow failed earlier at install). Added the
   dep (PR #109).
3. **scrub_text leak-oracle false positive** — the harness carved raw fuzzer
   bytes as synthetic map values; a short value like `"01"` (mapped to host_002)
   is a substring of the pseudonym `host_001`, so `scrub_text`'s **correct**
   output tripped `ensure_no_map_values`. Traced the exact 14-byte input and
   confirmed `scrub_text` itself is correct (it replaced everything it should;
   the "leak" was the `"01"` inside the inserted pseudonym). Fixed the harness to
   frame synthesized real values with a sentinel byte (0x01, absent from the
   pseudonym alphabet), making the oracle false-positive-free by construction
   (PR #109). **No change to `scrub_text` — no privacy bug.**

The Kani composed proof (HS-005) and the fuzz-no-panic property (HS-006) both
hold on develop @ c8c231a.
